# Scoped

`AddScoped<RequestTrace>()` registers a service that lives for one request. The container creates it when that request first asks, and drops it when the response is finished.

The store stays `AddSingleton`. A scoped store would forget the forecast after each response. `RequestTrace` is a second service. Its only state is an id created in the constructor.

```csharp
builder.Services.AddScoped<RequestTrace>();
builder.Services.AddScoped<RequestTraceReader>();

app.MapGet("/request-trace", (RequestTrace trace, RequestTraceReader reader) =>
    Results.Ok(new { trace = trace.Id, reader = reader.TraceId, sameInstance = ReferenceEquals(trace, reader.Trace) }));
```

`RequestTraceReader` takes `RequestTrace` in its constructor. The endpoint asks for both. The container builds the reader for this request and passes this request's trace into that constructor. `sameInstance` is true, and the two Guids match.

Send `GET /request-trace` again. The constructor runs again. The new response carries a different Guid, and `sameInstance` is still true.

| Request | Result |
| --- | --- |
| First `GET /request-trace` | 200. One Guid. `sameInstance` is true |
| Second `GET /request-trace` | 200. A different Guid. `sameInstance` is true |
| `POST /weatherforecast`, then `GET /weatherforecast/2026-10-05` | The stored forecast is still there. The store is the singleton from the previous lesson |

One program can register both lifetimes. The list is shared by every request. The trace belongs to one request.

Set a breakpoint in the `RequestTrace` constructor, and another on the first line of `MapGet("/request-trace")`. The first GET runs the constructor once, then `trace` and `reader.Trace` are that object. The second GET runs the constructor again.

Transient constructs a new object every time an endpoint or a constructor asks. That registration is the next lesson. `GET /transient-trace` returns two Guids.
