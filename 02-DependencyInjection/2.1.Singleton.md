# Singleton

`builder.Services.AddSingleton<WeatherForecastStore>()` registers one service. The container calls `new WeatherForecastStore()` the first time an endpoint asks for it, then keeps that object until the process stops.

```csharp
var builder = WebApplication.CreateBuilder(args);
builder.Services.AddSingleton<WeatherForecastStore>();
var app = builder.Build();

app.MapPost("/weatherforecast", (WeatherForecast forecast, WeatherForecastStore store) =>
{
    if (forecast.TemperatureC is < -90 or > 60)
        return Results.BadRequest(new { error = "temperatureC must be between -90 and 60." });

    store.Save(forecast);
    return Results.Created($"/weatherforecast/{forecast.Date:yyyy-MM-dd}", forecast);
});

app.MapGet("/weatherforecast/{date}", (DateOnly date, WeatherForecastStore store) =>
{
    var forecast = store.Find(date);
    return forecast is null ? Results.NotFound() : Results.Ok(forecast);
});
```

`forecast` still comes from the JSON body. `date` still comes from the path. `store` is not in the request. The container matches the parameter by its type, `WeatherForecastStore`. The parameter name can change and the same object is still passed in.

`GET /weatherforecast?days=2` does not take a store. That call does not create one. The first POST, GET by date, PUT, PATCH, or DELETE runs the constructor. The next request that takes a `WeatherForecastStore` does not run the constructor again. Both requests see the same list, so a forecast saved by POST is still there for GET.

`AddScoped<WeatherForecastStore>()` would construct a new store for each request. POST would save into one instance, and the following GET would search a different empty instance.

Stopping the app drops the singleton with the process. The list is still only in memory.

Set a breakpoint on `forecasts = []` inside the constructor, and another on the first line of `MapPost`. Send `GET /weatherforecast?days=2`: neither breakpoint runs. Send the POST: the constructor runs, then `store` is already that instance. Send `GET /weatherforecast/2026-10-05`. The constructor does not run. `store` is the same object, and `Find` returns the forecast from the POST.
