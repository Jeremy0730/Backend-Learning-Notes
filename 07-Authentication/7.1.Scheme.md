# Scheme

`ApiKeyAuthHandler` reads `X-Api-Key`. A match builds a principal with a name and a role. `GET /whoami` returns that name.

```csharp
protected override Task<AuthenticateResult> HandleAuthenticateAsync()
{
    if (!Request.Headers.TryGetValue("X-Api-Key", out var header))
        return Task.FromResult(AuthenticateResult.NoResult());

    var provided = header.ToString();
    if (provided.Length == 0)
        return Task.FromResult(AuthenticateResult.NoResult());

    if (MatchKey(provided, writerKey))
        return Task.FromResult(Success("writer", "writer"));

    if (MatchKey(provided, readerKey))
        return Task.FromResult(Success("reader", "reader"));

    return Task.FromResult(AuthenticateResult.Fail("The API key was rejected."));
}
```

`appsettings.Development.json` sets `ReaderKey` to `reader-key` and `WriterKey` to `writer-key`. `MatchKey` hashes the header and the configured value, then compares the hashes. An empty configured key matches nothing. The header value is not written into the response.

`Success` adds claim `Name` and claim `role`, and passes `Scheme.Name` into `ClaimsIdentity`, so the principal is authenticated. `NoResult` and `Fail` leave `/whoami` as `anonymous`.

The handler is constructed for the request. The first line of `HandleAuthenticateAsync` runs for `/whoami` and for the weather routes.

| Request | Result |
| --- | --- |
| `GET /whoami` | 200. `{ "name": "anonymous" }` |
| `GET /whoami` with `X-Api-Key: reader-key` | 200. `{ "name": "reader" }` |
| `GET /whoami` with `X-Api-Key: writer-key` | 200. `{ "name": "writer" }` |
| `GET /whoami` with `X-Api-Key: wrong-key` | 200. `{ "name": "anonymous" }` |
| `GET /weatherforecast?days=2` | 200. The route has no policy |

Set a breakpoint on the first line of `HandleAuthenticateAsync`. Send `GET /whoami` with `reader-key`. Step to `Success`. The response name is `reader`. Send `wrong-key` and stop on `Fail`. The response name is `anonymous`.
