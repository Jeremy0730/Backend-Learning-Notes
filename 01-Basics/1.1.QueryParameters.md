# Query parameters

`GET /weatherforecast?days=3` still hits the same route. `days` is a query parameter, not part of the path.

```csharp
app.MapGet("/weatherforecast", (int days = 5) =>
{
    const int maxDays = 14;
    if (days is < 1 or > maxDays)
    {
        return Results.BadRequest(new { error = $"days must be between 1 and {maxDays}." });
    }

    var forecast = Enumerable.Range(1, days).Select(/* one forecast per day */).ToArray();
    return Results.Ok(forecast);
});
```

The lambda parameter name must match the query key. The framework reads the string `"3"` and converts it to `int` before the lambda runs. Set a breakpoint on the first line inside the lambda: `days` is already `3`.

| Request | Result |
|---|---|
| `/weatherforecast?days=3` | 200, JSON array of 3 items |
| `/weatherforecast` | 200, JSON array of 5 items (`days` defaults to 5) |
| `/weatherforecast?days=0` | 400, `{ "error": "days must be between 1 and 14." }` |
| `/weatherforecast?days=abc` | 400 from the framework. The lambda does not run, because `"abc"` cannot become an `int` |

`Results.Ok` and `Results.BadRequest` set the status code and serialize the body. A direct `return forecast` would also be 200 with a JSON array. `BadRequest` is how this action reports a value that bound successfully but is out of range.

`SuperSimpleWebApplication.http` contains both calls: one with `?days=3`, and one with no query string.
