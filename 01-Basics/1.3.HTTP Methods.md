# HTTP methods

The method is the verb on the first line of a request. The path says which resource. The method says what to do with it.

This app uses two of them: `MapGet` handles GET, `MapPost` handles POST.

| Method | Role                              | Typical status                                 | In this app                                                  |
| ------ | --------------------------------- | ---------------------------------------------- | ------------------------------------------------------------ |
| GET    | Read a resource                   | 200, or 404 when it is missing                 | `GET /weatherforecast?days=2` generates forecasts. `GET /weatherforecast/2026-10-05` reads one stored forecast |
| POST   | Submit a new resource             | 201 when stored, 400 when the body is rejected | `POST /weatherforecast` stores one forecast                  |
| PUT    | Replace a resource at a known URL | 200 or 204, 404 when the URL does not exist    | Not implemented                                              |
| PATCH  | Change part of a resource         | 200 or 204, 400 when the change is invalid     | Not implemented                                              |
| DELETE | Remove a resource                 | 204, or 404 when it is already gone            | Not implemented                                              |

GET only reads. Calling it again returns data and leaves the stored list unchanged. POST writes. Calling it again for the same date replaces the stored forecast.

PUT and PATCH both update. PUT sends the whole forecast and replaces the stored one. PATCH sends only the fields that change, such as `{ "temperatureC": 18 }`. DELETE removes the forecast for that date.

Two properties used to tell these methods apart:

- **Safe** means the call does not change server state. GET is safe.
- **Idempotent** means repeating the same call leaves the same result. GET, PUT, and DELETE are idempotent. POST is not: each call is a new submission.
