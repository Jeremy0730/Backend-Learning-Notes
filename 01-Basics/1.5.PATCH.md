# PATCH

`PATCH /weatherforecast/2026-10-05` changes some fields of the forecast stored for that date. The body lists only the new values. Fields left out stay as they are.

POST stored `2026-10-05` with temperature 25 and summary `Mild`. This call then changes the temperature and leaves the summary:

```json
{ "temperatureC": 21 }
```

```csharp
app.MapPatch("/weatherforecast/{date}", (DateOnly date, WeatherForecastPatch patch) =>
{
    if (patch.TemperatureC is < -90 or > 60)
        return Results.BadRequest(new { error = "temperatureC must be between -90 and 60." });

    var index = forecasts.FindIndex(item => item.Date == date);
    if (index < 0)
        return Results.NotFound();

    var current = forecasts[index];
    var updated = current with
    {
        TemperatureC = patch.TemperatureC ?? current.TemperatureC,
        Summary = patch.Summary ?? current.Summary
    };
    forecasts[index] = updated;
    return Results.Ok(updated);
});
```

`WeatherForecastPatch` has `int? TemperatureC` and `string? Summary`. A JSON property that is missing arrives as null, and `??` keeps the stored value. `current with { ... }` copies the record and replaces those two properties. The list stores the copy. `date` stays the date from the URL. `temperatureF` is calculated again from the stored Celsius value.

A temperature outside `-90..60` is 400, and the list is not read. A missing date is 404, and nothing is added.

Send the same PATCH again. The status is still 200, and the stored forecast is still temperature 21 and summary `Mild`. This call sets a value, so repeating it leaves the same result.

| Request | Status | Meaning |
| --- | --- | --- |
| `PATCH` `{ "temperatureC": 21 }` after the POST above | 200 OK | Temperature is 21. Summary is still `Mild` |
| The same PATCH again | 200 OK | Still one item, with the same values |
| `PATCH` `{ "summary": "Warm" }` | 200 OK | Summary is `Warm`. Temperature stays 21 |
| `PATCH /weatherforecast/2026-01-01` | 404 Not Found | Nothing is added |
| `PATCH` `{ "temperatureC": 100 }` | 400 Bad Request | The stored forecast is unchanged |
| `PATCH` `{}` | 200 OK | The stored forecast is unchanged |

`summary` sent as JSON `null` also arrives as null, so this action keeps the stored label. It does not clear `summary`.

`SuperSimpleWebApplication.http` runs the PUT first, so the stored summary is `Cool` before the temperature PATCH. That PATCH leaves `Cool` in place. The next request sets `summary` to `Warm` and leaves the temperature.

DELETE removes the forecast for that date. That route is the next lesson.
