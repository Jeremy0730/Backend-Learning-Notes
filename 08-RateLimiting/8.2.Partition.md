# Partition

The limiter keeps one window per principal name. `writer-key` and `writer-b-key` both have role `writer`, so both pass the policy. Their names differ, so their counts are separate.

```csharp
if (MatchKey(provided, writerKey))
    return Task.FromResult(Success("writer", "writer"));

if (MatchKey(provided, writerBKey))
    return Task.FromResult(Success("writer-b", "writer"));
```

`reader-key` fails the `Writer` policy. Authorization returns 403 before `UseRateLimiter`, so that call does not take a permit from `writer`.

Send the file from the top after a restart. The reader post is first. Then two writer posts fill the `writer` window. The writer-b post still stores `2026-10-07`.

| Request, after a restart | Result |
| --- | --- |
| `POST` with `reader-key` | 403. The `writer` count stays at 0 |
| Two `POST`s with `writer-key` | 201, then 201. The `writer` window is full |
| `POST` `2026-10-07` with `writer-key` | 429 |
| `POST` `2026-10-07` with `writer-b-key` | 201. `GET /weatherforecast/2026-10-07` returns that forecast |

Set a breakpoint in `HandleForbiddenAsync`, and another inside `OnRejected`. The reader post stops in `HandleForbiddenAsync`. `OnRejected` does not hit. The third `writer-key` post hits `OnRejected`. The `writer-b-key` post hits `store.Save`.
