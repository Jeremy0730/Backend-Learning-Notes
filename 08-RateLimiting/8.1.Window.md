# Window

`PermitLimit` is 2 and `Window` is one minute. `QueueLimit` is 0, so the extra request is rejected immediately. Restart the app, then send the writer requests in order.

```csharp
RateLimitPartition.GetFixedWindowLimiter(
    httpContext.User.Identity?.Name ?? "anonymous",
    _ => new FixedWindowRateLimiterOptions
    {
        PermitLimit = 2,
        Window = TimeSpan.FromMinutes(1),
        QueueLimit = 0
    })
```

The policy name is `writes`. It is attached to the write group. `GET /weatherforecast?days=2` has no limiter.

The first two `writer-key` posts pass authorization, take a permit, and reach `store.Save`. The third post still has a writer principal. `OnRejected` writes 429 and `{ "error": "too many requests." }`. That forecast is not stored.

| Request, after a restart | Result |
| --- | --- |
| `POST` `2026-10-05` with `writer-key` | 201 |
| `POST` `2026-10-06` with `writer-key` | 201 |
| `POST` `2026-10-07` with `writer-key` | 429. The list has no `2026-10-07` |
| `GET /weatherforecast?days=2` | 200. This route is not limited |

Set a breakpoint on `WriteAsJsonAsync` inside `OnRejected`, and another on `store.Save`. The first two posts hit `store.Save`. The third hits `OnRejected` and does not hit `store.Save`.
