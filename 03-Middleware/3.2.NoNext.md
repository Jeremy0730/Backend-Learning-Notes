# No next

The second `app.Use` can answer the request itself. It writes the status and the body, then returns. `next` is not called, so the `Map*` lambda for that path does not run.

```csharp
app.Use(async (HttpContext context, RequestDelegate next) =>
{
    if (context.Request.Path.StartsWithSegments("/weatherforecast/blocked"))
    {
        context.Response.StatusCode = StatusCodes.Status403Forbidden;
        await context.Response.WriteAsJsonAsync(new { error = "this path is stopped by middleware." });
        return;
    }

    await next(context);
});
```

This delegate is registered after the middleware from the previous lesson and before the routes. A request enters the first middleware, then `next` enters this one.

`GET /weatherforecast/blocked` matches the `if`. The status is set to 403 before the body is written. `return` leaves this delegate. The first middleware continues at `var status` and logs 403. No route lambda runs. The response still has `X-Request-Path`, because the first middleware set that header before calling `next`.

Any other path falls through to `await next(context)` and reaches the endpoint, as in the previous lesson.

| Request | Result |
| --- | --- |
| `GET /weatherforecast/blocked` | 403. Body is `{ "error": "this path is stopped by middleware." }`. The route lambdas do not run |
| `GET /weatherforecast?days=2` | 200. This middleware calls `next`. The lambda builds the forecasts |
| Console line for the blocked GET | `GET /weatherforecast/blocked finished with 403` |

Set a breakpoint on the `if`, and another on the first line of `MapGet("/weatherforecast")`. Send the blocked GET. The `if` is true. Step over `return`. The `MapGet` breakpoint does not hit. The first middleware then reads `StatusCode` 403.
