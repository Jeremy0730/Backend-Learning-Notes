# Group

`MapGroup("/weatherforecast")` prefixes every route added to the group. `AddEndpointFilter` on the group applies to those routes. The temperature check is written once.

```csharp
var weather = app.MapGroup("/weatherforecast")
    .AddEndpointFilter<TemperatureFilter>();

weather.MapGet("/", (int days = 5, IOptions<WeatherSettings> settings) => { /* build forecasts */ });
weather.MapGet("/{date}", (DateOnly date, WeatherForecastStore store) => { /* store.Find */ });
weather.MapPost("/", (WeatherForecast forecast, WeatherForecastStore store) => { /* store.Save */ });
weather.MapPut("/{date}", (DateOnly date, WeatherForecast forecast, WeatherForecastStore store) => { /* store.Replace */ });
weather.MapPatch("/{date}", (DateOnly date, WeatherForecastPatch patch, WeatherForecastStore store) => { /* store.ApplyPatch */ });
weather.MapDelete("/{date}", (DateOnly date, WeatherForecastStore store) =>
    store.Remove(date) ? Results.NoContent() : Results.NotFound());
```

`MapPost("/")` is `POST /weatherforecast`. `MapPut("/{date}")` is `PUT /weatherforecast/2026-10-05`. The URLs match `04-Configuration`.

PUT still checks that the body date matches the URL. That check stays in the lambda. The filter runs first, so a temperature of `100` returns 400 before the date check.

| Request | Result |
| --- | --- |
| `PATCH` `{ "temperatureC": 100 }` after a stored forecast | 400. The stored forecast is unchanged. The lambda does not run |
| `PATCH` `{ "temperatureC": 21 }` | 200. The filter calls `next`. Summary stays as it was |
| `PUT` with body date `2026-10-06` on URL `2026-10-05` and temperature `18` | 400 from the lambda. `date in the body must match the URL.` |
| `DELETE /weatherforecast/2026-10-05` | 204. The filter calls `next` |

Set a breakpoint on the first line of `InvokeAsync`, and another on the first line of `MapPatch`. Send the PATCH with temperature `100`. Only the filter breakpoint hits. Send `{ "temperatureC": 21 }`. Both hit, and `patch.Summary` is null.
