# Context

`WeatherDbContext` owns a `DbSet<ForecastRow>`. The key is the date. `Save` inserts a row or updates the row for that date, then `SaveChangesAsync` writes the file.

```csharp
internal async Task Save(WeatherForecast forecast)
{
    var row = await db.Forecasts.FirstOrDefaultAsync(item => item.Date == forecast.Date);
    if (row is null)
    {
        db.Forecasts.Add(new ForecastRow
        {
            Date = forecast.Date,
            TemperatureC = forecast.TemperatureC,
            Summary = forecast.Summary
        });
    }
    else
    {
        row.TemperatureC = forecast.TemperatureC;
        row.Summary = forecast.Summary;
    }

    await db.SaveChangesAsync();
}
```

In `02-DependencyInjection` the store was a singleton, because a new list on each request would forget the previous POST. This store is scoped. The context is scoped, and the container will not give a scoped context to a singleton. Each request gets a new store and a new context. Both requests open the same `forecasts.db`.

`EnsureCreated` runs in a scope during startup and then that scope is disposed. A request does not run it again.

| Request | Result |
| --- | --- |
| `GET /weatherforecast?days=2` | 200. The store constructor does not run |
| `POST` `2026-10-05` with `writer-key` and temperature `25` | 201. `forecasts.db` appears in the project folder |
| `GET /weatherforecast/2026-10-05` | 200. Temperature is 25 and summary is `Mild`. `temperatureF` is calculated |
| The same POST again | 201. The table still has one row for that date |

Set a breakpoint on `EnsureCreated`, and another in the store constructor. Start the app. `EnsureCreated` runs, and the constructor does not. Send `GET /weatherforecast?days=2`. The constructor does not run. Send the POST. The constructor runs, then `SaveChangesAsync` runs. Send the GET by date. The constructor runs again, on a new store, and `Find` returns the row.
