# Preflight

A browser sends `OPTIONS` before a page calls `POST` with `Content-Type` and `X-Api-Key`. That request asks which origin, method, and headers are accepted. It carries no API key.

```csharp
policy.WithOrigins("http://localhost:5173")
    .WithMethods("GET", "POST", "PUT", "PATCH", "DELETE")
    .WithHeaders("Content-Type", "X-Api-Key")
```

`UseCors` sees `Origin`, `Access-Control-Request-Method`, and `Access-Control-Request-Headers`. For `http://localhost:5173` it writes the allow headers and returns 204. `next` is not called. `MapPost` does not run, and the handler does not read a key.

| Request | Result |
| --- | --- |
| `OPTIONS /weatherforecast` with `Origin: http://localhost:5173`, method `POST`, headers `content-type,x-api-key` | 204. `Access-Control-Allow-Origin` is `http://localhost:5173`. The allow-headers value includes `X-Api-Key` |
| The same `OPTIONS` with `Origin: http://localhost:9999` | 204. The response has no `Access-Control-Allow-Origin` |

Set a breakpoint on the first line of `MapPost`, and another on the first line of `HandleAuthenticateAsync`. Send the allowed `OPTIONS`. Neither breakpoint hits.
