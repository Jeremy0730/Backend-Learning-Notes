# Origin

`WithOrigins` lists one origin. The value is the scheme, the host, and the port together: `http://localhost:5173`.

A `GET` with `Origin: http://localhost:5173` returns 200, and the response includes `Access-Control-Allow-Origin: http://localhost:5173`. A `GET` with `Origin: http://localhost:9999` also returns 200 and the forecast JSON. That response has no `Access-Control-Allow-Origin`.

The `.http` file shows that JSON. A page loaded from `http://localhost:9999` does not receive it: the browser withholds a response whose allow-origin header is not that page's origin.

The allow-origin header does not store a forecast. `POST` with `Origin: http://localhost:5173` and no `X-Api-Key` is still 401. The same POST with `writer-key` is 201, and the 201 response includes `Access-Control-Allow-Origin` for `http://localhost:5173`.

| Request | Status | `Access-Control-Allow-Origin` |
| --- | --- | --- |
| `GET /weatherforecast?days=2` with `Origin: http://localhost:5173` | 200 | `http://localhost:5173` |
| `GET /weatherforecast?days=2` with `Origin: http://localhost:9999` | 200 | absent |
| `POST` with the allowed origin and no key | 401 | `http://localhost:5173` |
| `POST` with the allowed origin and `writer-key` | 201 | `http://localhost:5173` |

Set a breakpoint on the first line of `MapGet("/")`. Send the `GET` with `Origin: http://localhost:9999`. The lambda runs and returns 200. The response headers have no `Access-Control-Allow-Origin`.
