# Order

The logger is registered first. The catch is registered second. A request enters the logger, then `next` enters the catch, then `next` enters the endpoint.

```csharp
app.Use(async (HttpContext context, RequestDelegate next) =>
{
    var method = context.Request.Method;
    var path = context.Request.Path.Value ?? "/";
    context.Response.Headers.Append("X-Request-Path", path);
    await next(context);
    var status = context.Response.StatusCode;
    app.Logger.LogInformation("{Method} {Path} finished with {Status}", method, path, status);
});

app.Use(async (HttpContext context, RequestDelegate next) =>
{
    try
    {
        await next(context);
    }
    catch (Exception exception)
    {
        app.Logger.LogError(exception, "the request failed.");
        context.Response.StatusCode = StatusCodes.Status500InternalServerError;
        await context.Response.WriteAsJsonAsync(new { error = "the request failed." });
    }
});
```

`GET /crash` sets `X-Request-Path` in the logger, then throws inside the catch's `next`. The catch writes 500 and returns. The logger continues at `var status` and reads 500.

The header is set before `next`, as in `3.1.Use`, so it is already on the response when the catch writes the body.

`TemperatureFilter` is on the weather group. `/crash` does not enter it. `GET /weatherforecast?days=2` enters the logger, the catch, the filter, and the lambda. The catch block does not run.

| Request | Header | After the catch returns |
| --- | --- | --- |
| `GET /crash` | `X-Request-Path: /crash` | Status 500. The logger writes `GET /crash finished with 500` |
| `GET /weatherforecast?days=2` | `X-Request-Path: /weatherforecast` | Status 200. The catch does not log an error |

Set a breakpoint on `var method`, and another on `throw`. Send `GET /crash`. The logger hits first, and `path` is `/crash`. Step into `await next`, then into the catch's `next`, and stop on `throw`. After the catch returns, `status` in the logger is 500.
